# Expense Tracker API

Backend for tracking expenses. Work in progress.

## Getting started

**Prerequisites:** Node 22 and Docker Desktop.

1. Start Postgres:
   ```bash
   docker run --name expense-db \
     -e POSTGRES_PASSWORD=devpassword \
     -e POSTGRES_DB=expense_api \
     -p 5432:5432 \
     -v expense-pgdata:/var/lib/postgresql/data \
     -d postgres:17
   ```
   *If the container name or port is taken, see `docker ps -a`.*
2. Configure the environment: `cp .env.example .env`
3. Edit `.env` and replace the `JWT_SECRET` placeholder with a long random value. Generate one with:
   ```bash
   openssl rand -base64 48
   ```
4. Install dependencies: `npm install`
5. Create the tables: `npx prisma migrate deploy`
6. Generate the Prisma client: `npx prisma generate`
7. Start the API: `npm run dev`
8. Check it: `curl localhost:3000/health`

Next time, just run `docker start expense-db` and `npm run dev`.

## Endpoints

| Method | URL | What it does | Success | Errors |
| --- | --- | --- | --- | --- |
| POST | `/auth/register` | Register a user. | 201 | 400 (invalid body), 409 (email already registered) |
| POST | `/auth/login` | Log in and receive a token. | 200 (`{ token }`) | 400 (invalid body), 401 (invalid credentials) |
| POST | `/expenses` | Create an expense. | 201 | 400 (invalid body or `categoryId` does not exist) |
| GET | `/expenses` | List expenses. | 200 | 400 (invalid query params) |
| GET | `/expenses/:id` | Get one expense. | 200 | 400 (invalid id), 404 (not found) |
| PUT | `/expenses/:id` | Replace an expense. | 200 | 400 (invalid id, invalid body, or `categoryId` does not exist), 404 (not found) |
| DELETE | `/expenses/:id` | Delete an expense. | 204 | 400 (invalid id), 404 (not found) |
| POST | `/categories` | Create a category. | 201 | 400 (invalid body), 409 (category name already exists) |
| GET | `/categories` | List categories. | 200 | None |
| GET | `/categories/:id` | Get one category. | 200 | 400 (invalid id), 404 (not found) |
| PUT | `/categories/:id` | Replace a category. | 200 | 400 (invalid id or invalid body), 404 (not found), 409 (category name already exists) |
| DELETE | `/categories/:id` | Delete a category. | 204 | 400 (invalid id), 404 (not found), 409 (expenses are still attached) |

### Authentication

Every route except `/health` and `/auth/*` requires an `Authorization: Bearer <token>` header. Login tokens expire after 15 minutes. A missing or invalid token returns **401 Unauthorized**.

Expenses belong to the user who created them, and each user can only see and manage their own expenses. Categories are shared between users for now. Requesting another user's expense returns **404 Not Found**, the same response as for an expense that does not exist.

Invalid request bodies, query params, ids, and expense category references return **400 Bad Request**.
Deleting a category that still has expenses is blocked with **409 Conflict** so those expenses
aren't left without a category.
Category names are trimmed before storing and comparing; names are compared case-insensitively,
so `Food`, `food`, and ` Food ` count as the same name.

### Expense list query params

- `month=YYYY-MM` filters expenses to a calendar month, such as `month=2026-10`; an invalid month returns 400.
- `categoryId=3` filters expenses to the specified category ID; an invalid ID returns 400.
- `page=1` selects the page; must be a positive integer. Defaults to `1`.
- `limit=20` sets the number of expenses per page; must be a positive integer, up to `100`. Defaults to `20`.

The `GET /expenses` response is paginated:

```json
{
  "items": [],
  "page": 1,
  "limit": 20,
  "total": 0
}
```

`items` contains the expenses for the requested page, and `total` is the number of matching expenses across all pages.

### Data shapes and required fields

- **Expense:** `id` (number, generated by the API), `amount` (positive integer number of paise; ₹50.00 is `5000` and ₹0.50 is `50`), `description` (string), `date` (valid calendar date in `YYYY-MM-DD` format), `categoryId` (number).
  - **Required on POST:** `amount`, `description`, `date`, and `categoryId`. The API generates `id`.
  - `amount` must be an integer greater than 0. The API sends and receives amounts in paise, never rupees.
  - Convert to rupees only at the frontend: divide paise by 100 for display and convert user-entered rupees to paise (for example, `Math.round(rupees * 100)`).
- **Category:** `id` (number, generated by the API), `name` (string).
  - **Required on POST:** `name`. The API generates `id`.
